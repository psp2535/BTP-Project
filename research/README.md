# IM-VRM Research Project Audit and Manuscript Generation

This directory contains the outputs of a rigorous, 14-phase research audit and refinement process for the IM-VRM project. The goal of this process was to elevate the existing codebase and draft into a top-tier, publication-quality research paper.

## Directory Structure
```
research/
├── paper.tex                # The final, revised IEEEtran LaTeX manuscript
├── references.bib           # BibTeX references for the paper
├── experiments/             # Python scripts for missing empirical evaluations
│   ├── run_fleet_scalability.py
│   └── run_hyperparam_sensitivity.py
├── review/                  # Deep audits, literature gap, and simulated peer reviews
│   ├── novelty_audit.md

```

## 1. Running the Missing Experiments
To ensure empirical rigor and address the research questions (RQ3, RQ4) formulated during the audit, run the provided experiment scripts from the `research/experiments/` directory.

Ensure you have your environment set up and the `data/processed/` directory contains the prerequisites (e.g., `node_embeddings.pt`, `synthetic_fleet.json`) generated by `main.py`.

```bash
cd research/experiments/
python run_fleet_scalability.py
python run_hyperparam_sensitivity.py
```
The results will be saved automatically as CSV files in the `research/tables/` directory.

## 2. Compiling the LaTeX Manuscript
The `paper.tex` file has been written to strictly adhere to the IEEEtran conference format. It incorporates the tightened narrative, the 137-dimensional state tensor formulation, and the ablation/scalability results.

To compile the paper:
```bash
cd research
pdflatex paper.tex
bibtex paper
pdflatex paper.tex
pdflatex paper.tex
```

## 3. Reviewer Feedback
Before final submission to a venue like **IEEE T-ITS** or **KDD**, please read the simulated reviewer feedback in `research/review/`. The paper narrative has been adjusted to mitigate the risks (primarily over-claiming theoretical ML novelty vs. emphasizing the strong applied systems integration). However, you must carefully evaluate the "Limitations" (single-dataset reliance) before submission.
